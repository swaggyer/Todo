# 源码结构与维护

## 单套界面，多端构建

`packages/ui` 是界面、样式、业务逻辑及资源的唯一维护来源。`pnpm build` 从共享源码生成：

- `apps/web/dist`：可独立托管的网页版。
- `apps/mobile/www`：随原生应用安装的网页资源。

Capacitor 把手机端资源同步至 Android 和 iOS 工程。手机应用包含本地页面，日常使用无需加载原 Sites 网站。

不要直接修改 `dist`、`www`，或原生工程中复制的网页资源；重新构建时这些内容会被覆盖。Android 的 Java、资源与 Gradle 配置，以及 iOS 的 Swift、Info.plist 和 Xcode 配置则属于各平台原生源码，应在各自工程中维护。

## 主要目录

| 位置 | 责任 |
| --- | --- |
| `packages/ui` | 页面、动画、卡片、待办逻辑、随记与资源 |
| `apps/web` | Web 平台配置与静态构建产物 |
| `apps/mobile` | Capacitor 配置、手机适配与 Android / iOS 工程 |
| `scripts` | 开发服务器、构建、静态检查与压缩打包 |
| `docs` | 开发、数据迁移、部署及构建说明 |
| `.github/workflows` | CI 和手动产物构建 |

## 保持现有行为

- 默认界面为纯白背景，深色高饱和卡片；字体与交互沿用已有设计。
- Today 根据设备本地日期筛选 `start <= today <= end` 的事项。
- 一日、一周和自定义控制有效日期范围；完成后不会每天生成新副本。
- 每个事项保存自己的完成状态；多日事项完成后在整个日期范围内保持完成。
- 数据保存在设备本地；待办和随记使用稳定 ID。
- 数据库名保持 `little-days-v1`，避免同一网站来源内的版本升级改变已有存储位置。
- 导入备份合并缺失 ID，已有 ID 的本地记录优先。

部署到新域名、从 Web 转到原生应用，或重装手机应用会使用另一个存储容器。相同数据库名并不代表这些容器可以自动共享数据。

## 修改后的验证

```sh
pnpm check
pnpm build
pnpm mobile:sync
```

检查桌面和手机宽度下的 Today、Lists、随记；创建、编辑、完成和删除待办；保存带照片的随记；导出后在另一环境导入备份。手机端再检查系统相机、照片选择、返回操作与安全区域。

网页版能够正常运行，不能代替 Android 和 iPhone 真机验证。原生工程编译与界面运行应分别确认。
